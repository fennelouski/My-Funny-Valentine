## What is implemented

Thirty existing starter IDs now open detached drafts with six visual families and five layout variants. The six original illustrated assets are reused, alongside native vector print geometry. This is not thirty new generated illustrations. Old saved layouts stay on the classic drawing path. The optional versioned composition is encoded in the existing layout JSON, so the SwiftData schema and card relationships stay intact. Unknown future composition families preserve the remaining classic layout.

A frozen render snapshot copies message, note, geometry and image bytes. The native preview uses a local phase and manual tap/drag opening. The full-card GIF has a three-second, thirty-frame opening/closing loop without requiring a face. Its renderer also produces static front/inside PNGs, a transparent square PNG chat image under 500 KB, and a printable front plus readable inside continuation pages. The print wrapper opens the native user-controlled dialog. Sharing keeps the ordinary ShareLink chooser for Mail/chat/file destinations; no recipient or print job is chosen automatically.

The offline HTML file embeds sixteen opening-half-cycle native frames, escaped full text, a keyboard-accessible button and pointer drag. Its CSS perspective is decorative; the card contents remain native-rendered pixels. It has no CDN, remote script, tracking or WebGL requirement. A content security policy rejects external resources. A PNG chat image does not install a Messages, WhatsApp or Telegram sticker pack. A real Messages extension remains a separate future target.

Image Playground retains the interactive system sheet. The current installed 26.5 SDK supports sourceImage and style selection, including externalProvider since 26.0. Apple owns provider setup/consent. No ImageCreator or private API is used. The new closest-size and hinge APIs are absent from this SDK, so they are documented instead of fabricated.

## Research decisions

Apple actually announced [iPhone Duo with iOS 27](https://www.apple.com/newsroom/2026/09/apple-unveils-iphone-duo/). The [Duo developer page](https://developer.apple.com/iphone-duo/) specifies Xcode 27.1 beta. [Hinge input](https://developer.apple.com/videos/play/tech-talks/111464/) can drive a card-opening effect; layout uses arrangement/reserved-region APIs. The actual [onHingeChange DocC metadata](https://developer.apple.com/tutorials/data/documentation/swiftui/view/onhingechange(isenabled:_:).json) reports iOS/iPadOS 27.1 beta. This candidate's manual interaction works without that SDK or hardware; no physical hinge verification is claimed.

Apple's [interactive Image Playground session](https://developer.apple.com/videos/play/wwdc2026/375/) explains its newer styles, external-provider choice and size hints. [ImageCreator is discontinued on OS 27](https://developer.apple.com/news/?id=dz9wvq0r), making the existing sheet the correct integration. Size hints need a newer SDK than the installed one. System-managed provider usage is separate from app-managed OAuth.

The official [Sign in with ChatGPT overview](https://developers.openai.com/siwc), [September 28 cookbook](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt), [preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) and [authorization contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) were opened after inspecting local integration records. Personal/open-source eligibility or selected commercial approval is required; identity and permission to spend plan usage are separate. Image generation is unsupported in this preview. The owner's access-request authorization is not an issued app client or provider approval. This candidate adds no dead-end connect button, token access, hosted image calls or shared backend billing. Approved text suggestions can be added after real capability/callback setup and validation.

Apple [deprecated OpenGL ES](https://developer.apple.com/library/archive/documentation/3DDrawing/Conceptual/OpenGLES_ProgrammingGuide/Introduction/Introduction.html). Keeping the existing CoreGraphics engine gives native previews and printable/static frames one source. A future web editor can consume a versioned scene format, but replacing this working engine with OpenGL/WebGL is unnecessary for these card interactions. The standalone browser export already works without either graphics framework.

## Historical prepared verification plan

The plan below predates the actual current checks recorded above. Pending items listed here are historical planning statements; the current receipts distinguish completed and unexecuted checks.

Then enumerate and run the thirteen new export/isolation tests plus the existing CardRenderer/CardDraft/CardPersistence/StarterTemplate methods only. Do not count zero tests as a pass. Existing old UI tests remain historical and should not be run unmodified as new release proof. Their legacy `--uitesting` requests without a UUID now intentionally open a blank rejected host.

Three new iOS UI methods are prepared for genuine native verification. They use an explicit fresh session UUID, require its accessibility marker before interaction, and capture full-screen pixels plus accessibility text before actions. They exercise each starter family and actual opening/closing, saved text and motion-off after relaunch, the real local export sheet, and rejection of an invalid private session. Provider generation, Photos access, Image Playground and printing are unavailable in this private process. No share destination is selected. These methods do not prove that a native chooser or print dialog has opened; those remain separate owner-controlled checks.

Native Phone/Pad/Mac checks should exercise a starter, immediate editable words, each family, tap/drag/open/close, save/reopen and explicit motion-off; front/inside PNG, GIF, PDF and HTML export; real user-controlled share/print dialog open/dismiss without selecting a destination; long labels/large text, dark appearance, narrow Mac windows and unchanged keyboard shortcuts. Capture full-screen native pixels and review in one bounded platform batch, then at most one correction batch. Image Playground needs separate supported-device consent/capability checks. No iOS 27.1, real hinge, provider billing, automatic sending, native sticker-extension or cloud-sync success is claimed.
